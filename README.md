# GameDev Hub

게임 개발팀의 **Task · 에셋 · 코드 변경 이력**을 Task ID 중심으로 연결하는 경량 협업 허브.
[개발 계획서](../gamedev_hub_development_plan.html)의 MVP 범위(Phase 1~3)와 4단계 통합 Change Feed를
**빌드 도구·외부 의존성 없이 동작하는 정적 웹앱**으로 구현했습니다. GitHub Pages에 그대로 올리면 됩니다.

---

## 1. 빠른 시작

ES 모듈을 사용하므로 `file://` 로 직접 열면 동작하지 않습니다. 정적 서버로 실행하세요.

```bash
cd gamedev-hub
python3 _local/serve.py          # 또는 python3 -m http.server 8080
# 앱        → http://localhost:8080/
# 화면 미리보기 → http://localhost:8080/_local/preview.html
```

접속 승인을 서버에서 검증하므로 먼저 4장의 Apps Script 백엔드를 배포해야 합니다. 첫 화면에서 웹앱 URL을
입력하고 **최초 관리자** 계정을 만든 뒤 로그인하세요. 이후 일반 사용자는 회원가입 후 관리자 승인을 받아야
접속할 수 있습니다. 로그인 후 로컬 어댑터를 선택하면 데이터 자체는 브라우저 localStorage에 저장할 수 있습니다.

`_local/preview.html` 은 11개 화면을 목록/그리드로 한 번에 보고, 모바일~데스크톱 뷰포트를 전환하고,
데모·대용량·빈 상태 데이터를 즉시 바꿔가며 확인하는 하네스입니다.
**`_local/` 은 배포물이 아니며 앱은 이 폴더 없이 동작합니다**(자세한 내용은 `_local/README.md`).

## 2. GitHub Pages 배포

빌드 단계가 없으므로 파일을 그대로 올리면 끝입니다.

1. 이 폴더를 저장소에 커밋 (예: `docs/` 또는 저장소 루트).
2. **Settings → Pages → Source: Deploy from a branch** 에서 브랜치와 폴더를 선택.
3. `https://<계정>.github.io/<저장소>/gamedev-hub/` 로 접속.

* 라우팅은 해시(`#/tasks/GAME-142`) 기반이라 404 리라이트 설정이 필요 없습니다.
* `.nojekyll` 이 포함되어 있어 Jekyll 전처리가 비활성화됩니다.
* 모든 자산이 상대 경로라 하위 경로 배포에서도 그대로 동작합니다.

## 4. 저장소 어댑터

계획서 15장의 "외부 서비스 추상화" 원칙에 따라 **도메인 로직과 저장 방식을 분리**했습니다.
어댑터는 테이블 입출력만 담당하고, 락 상태 머신·버전 증가·변경 로그 등 업무 규칙은 전부
`js/domain/repo.js` 한 곳에 있습니다.

| 어댑터 | 저장 위치 | 용도 |
|---|---|---|
| `LocalAdapter` (기본) | 브라우저 localStorage | 데모, 1인 사용, 오프라인 |
| `GasAdapter` | Google Sheets + Drive | 팀 공유. `apps-script/Code.gs` 배포 필요 |

새 백엔드(FastAPI, Spring, PostgreSQL 등)를 붙일 때는
`list / insert / update / remove / replaceAll` 다섯 메서드만 구현해 `js/adapters/index.js` 에 등록하면 됩니다.
동시성은 `update(table, id, patch, { expect })` 의 조건부 갱신(CAS)으로 처리하므로,
체크아웃 경합 같은 규칙이 백엔드가 바뀌어도 유지됩니다.

### Apps Script 백엔드 배포

1. 새 스프레드시트 → **확장 프로그램 → Apps Script** 에 `apps-script/Code.gs` 붙여넣기.
2. `SHARED_TOKEN` 을 길고 무작위인 관리자 설정 키로 변경, 업로드를 쓸 경우 `DRIVE_FOLDER_ID` 지정
   (리비전 이력을 남기려면 서비스에서 *Drive API* 도 추가).
3. **배포 → 새 배포 → 웹 앱** (실행: 나 / 액세스: 링크가 있는 모든 사용자).
4. 발급된 `/exec` URL 을 `js/config.js` 의 `DEFAULT_GAS_ENDPOINT` 에 넣습니다. 그러면 팀원은
   로그인할 때 URL을 붙여넣지 않아도 됩니다(비워두면 로그인 화면에 입력칸이 나타납니다).
5. **최초 관리자** 탭에서 설정 키(`SHARED_TOKEN`)와 관리자 정보를 입력해 관리자 계정을 만듭니다.
6. 관리자 로그인 → **설정 → 계정 승인**에서 가입 신청을 승인하거나 거절.

> **웹앱 URL을 코드에 넣어도 되나요?** 됩니다. URL은 주소일 뿐이고 `register`·`login` 을 뺀 모든 액션은
> 서버에서 로그인 세션 검사를 통과해야 합니다. 반대로 **`SHARED_TOKEN` 은 절대 코드에 넣지 마세요.**
> 최초 관리자 생성의 유일한 방어선이라, 공개되면 누구나 관리자를 만들 수 있습니다.

시트는 첫 호출 시 테이블별로 자동 생성되며, 헤더는 `js/domain/schema.js` 의 `COLUMNS` 와 동일합니다.

### 배포 후에 연결해도 됩니다

연결 정보와 로그인 세션은 **빌드에 포함되지 않고 브라우저 localStorage에만 저장**됩니다.
따라서 GitHub Pages에 먼저 올린 뒤, 배포된 페이지의 *설정 → 저장소 어댑터*에서 URL과 토큰을 넣고
**연결 적용**을 누르면 그 순간부터 Sheets를 사용합니다. 재배포·재빌드는 필요 없습니다.

* *연결 적용* 은 먼저 `ping` 을 호출해 **성공했을 때만** 전환합니다. 실패하면 이유를 토스트로 보여주고
  기존 저장소를 그대로 유지합니다(설정이 깨져 화면이 먹통이 되지 않습니다).
* 전환 후 새로고침해도 유지되며, 나중에 웹앱이 응답하지 않으면 자동으로 로컬 저장소로 되돌아갑니다.
* Apps Script URL은 **브라우저마다** 저장되므로 팀원 각자 로그인 화면에서 한 번씩 입력해야 합니다.
* 로컬에서 만든 데이터를 옮기려면 *설정 → JSON 내보내기* → 어댑터 전환 → *가져오기(덮어쓰기)* 순서로 하세요.
* 전환 시 데모 데이터가 팀 시트에 들어가는 일은 없습니다(빈 시트면 빈 상태로 시작합니다).

Apps Script 쪽에서 자주 막히는 지점:

| 증상 | 원인·해결 |
|---|---|
| "JSON이 아닌 응답을 반환했습니다" | 웹앱 액세스가 *링크가 있는 모든 사용자* 가 아님 → 로그인 페이지가 대신 반환됨. 배포 설정 변경 |
| "로그인이 필요합니다" | 세션 만료 또는 다른 배포본의 세션 → 다시 로그인 |
| "관리자 설정 키가 올바르지 않습니다" | 배포된 버전의 `SHARED_TOKEN` 과 입력값 불일치 |
| 코드를 고쳤는데 반영 안 됨 | *배포 관리 → 편집 → 버전: 새 버전* 으로 다시 배포해야 함(`/exec` URL은 유지됨) |
| 파일 업로드 실패 | `DRIVE_FOLDER_ID` 미설정. 리비전 이력을 남기려면 서비스에서 *Drive API* 추가 |

## 5. GitHub 연동 (정적 호스팅에서의 Webhook 대체)

정적 호스팅에는 Webhook 수신 서버를 둘 수 없으므로 **REST 폴링 + 키 파싱**으로 대체했습니다.

```
GitHub REST (commits / pulls)
      → 메시지·브랜치명에서 GAME-142 추출
      → 존재하는 Task에만 연결 (중복 자동 스킵)
      → GitLinks 저장 + ChangeLog 기록 → 통합 피드
```

* 설정 또는 프로젝트 편집에서 `owner/repo` 를 지정합니다.
* 공개 저장소는 토큰 없이 동작합니다(시간당 60회). 비공개 저장소나 한도 상향에는
  `public_repo`/`repo` 스코프의 토큰이 필요하며, 토큰은 해당 브라우저의 localStorage에만 저장됩니다.
  **공용 PC에서는 토큰을 저장하지 마세요.**
* 나중에 서버를 두면 Webhook 핸들러가 `importGitEvents()` 에 동일한 형태의 이벤트만 넘기면 됩니다.

## 6. 구조

```
gamedev-hub/
├─ index.html              앱 셸 (사이드바 · 상단바 · 뷰 아웃렛)
├─ css/style.css           단일 스타일시트 (토큰 기반, 반응형)
├─ js/
│  ├─ config.js            배포 설정 — Apps Script URL, 업로드 상한
│  ├─ main.js              부트스트랩 · 라우팅 · 이벤트 위임 · 렌더 루프
│  ├─ core/                dom(안전한 템플릿) · util · store · router · ui(모달/토스트)
│  ├─ adapters/            base(계약) · local · gas · github · index(팩토리)
│  ├─ domain/              schema(스키마/상수) · repo(업무 규칙) · seed(데모 데이터)
│  └─ views/               화면별 모듈 + components(공용 조각) + dialogs(공용 폼)
├─ apps-script/Code.gs     Google Sheets/Drive 백엔드 (선택)
├─ logs/                   작업 로그 — 결정 이유와 변경 이력 기록
└─ _local/                 로컬 전용 하네스 — 배포 제외 대상 (서버 · 미리보기 · 테스트)
```

배포에 필요한 것은 `index.html`, `css/`, `js/`, `.nojekyll` 뿐입니다.
`apps-script/` 는 참고용 소스, `_local/` 은 개발용이며 둘 다 없어도 앱은 동작합니다.

설계 규칙 몇 가지:

* **뷰는 순수 함수**에 가깝습니다. `render(ctx) → HTML` 이고, 상호작용은
  `actions`(클릭) / `changes`(변경) / `submits`(제출) 맵으로 선언합니다. 리스너는 `main.js`가
  단 한 번 위임 등록하므로 화면 전환 시 해제 누락이 생기지 않습니다.
* **모든 보간은 기본 이스케이프**됩니다(`js/core/dom.js`의 `html` 태그드 템플릿). 원문 삽입은 `raw()`로만 가능합니다.
* **상태는 한 방향**입니다. 변경 → `repo` 이벤트 → 전체 다시 그리기. 부분 갱신 최적화를 넣지 않아
  화면과 데이터가 어긋날 여지를 없앴습니다.
* 스키마·상수·열 정의는 `js/domain/schema.js` 한 곳에만 있습니다(내보내기·Apps Script 헤더 공용).

## 7. 테스트

테스트는 전부 `_local/` 안에 있습니다(앱 트리에는 테스트 파일도 `package.json` 도 없습니다).

```bash
cd _local
npm test           # 의존성 없이: 도메인 35 · 뷰 18 · GAS 계약 25 · 분리/라우트 8
npm i              # jsdom 설치 (최초 1회)
npm run test:all   # 위 + 부팅 통합 31 · 미리보기 하네스 12  (총 129 케이스)
```

검증 범위: Task 채번/변경 로그 요약, 에셋 락 상태 머신(동시 체크아웃 거부·체크인 버전 증가),
파일 드롭 업로드(Drive 호출·v1 생성·중복 이름 거부·업로드 미지원 저장소 차단),
Git 이벤트 매핑과 중복 스킵, 통합 피드 정렬/필터, 내보내기·가져오기, 라우팅, 모달 폼, 검색 필터,
팀 동기화(다른 탭의 변경 반영·쓰기 중 건너뜀·조회 실패 시 스냅샷 보존·CAS 충돌 후 자동 최신화),
영속화, 그리고 **앱이 로컬 하네스에 의존하지 않는지**까지 자동 확인합니다.

## 8. 현재 제한과 다음 단계

* 동기화는 전체 스냅샷을 다시 읽는 방식이라 `reload` 1회가 테이블 수만큼(8회) 요청을 씁니다.
  호출량이 문제가 되면 `Code.gs` 에 `listAll` 액션을 추가해 1회로 줄일 수 있습니다(백엔드 재배포 필요).
* 실시간 푸시(Webhook·SSE)는 정적 호스팅 제약으로 없습니다. 주기 동기화가 대신하며, 자동 동기화는
  탭이 활성 상태이고 입력·모달·드래그 중이 아닐 때만 실행됩니다(설정에서 주기 변경·끄기 가능).
* 로컬 어댑터는 브라우저별 저장이라 팀 공유가 안 됩니다 → Apps Script 어댑터로 전환.
* Drive 실제 업로드는 Apps Script 어댑터에서만 동작합니다. 파일 본문을 브라우저에 저장하지 않기 때문에
  로컬 어댑터에서는 드롭존을 아예 표시하지 않고, 체크인 시에도 메타데이터·해시만 기록합니다.
* 업로드는 파일을 base64로 실어 보내므로 파일당 상한이 있습니다(`js/config.js` 의 `MAX_UPLOAD_MB`, 기본 20MB).
  더 큰 원본은 Drive에 직접 올리고 링크만 등록하세요.
* 이미지 미리보기는 Drive 썸네일 URL을 그대로 씁니다. 해당 Drive 파일에 접근 권한이 있는 계정으로
  로그인한 브라우저에서만 보입니다.
* Git은 폴링이라 실시간이 아닙니다 → 서버 도입 시 Webhook으로 교체.
* 계획서 13장 5단계(AI 기능: 회의록 Task 추출, 변경 영향 분석)는 백엔드 도입 이후 과제입니다.
